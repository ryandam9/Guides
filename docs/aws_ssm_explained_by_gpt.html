AWS Systems Manager Session Manager lets you open a shell on a private EC2 instance without an SSH key, Linux password, public IP address, or inbound SSH port. Your IAM role authorizes the connection. The SSM Agent on EC2 uses outbound encrypted connections to AWS messaging endpoints. Session Manager carries commands and output between your laptop and the agent. The instance needs a route to AWS through VPC endpoints or a NAT gateway.

You connect from your laptop to a private EC2 instance. You have no SSH key, no public IP address, and no Linux password. How? Your IAM role authorizes the session. An agent inside EC2 carries your shell traffic through AWS.

5. Check this on your own setup

Run these on your laptop:

Then run these inside the resulting EC2 session:

whoami
id
sudo systemctl status amazon-ssm-agent
ip addr

Your corporate ADFS or IAM Identity Center login can provide temporary AWS credentials. They are not SSH keys and do not authenticate a Linux account.

6. What about audit and security?

CloudTrail can record session-management API calls. Session Manager can send supported shell-session logs to CloudWatch Logs or S3 when configured. SSH-over-Session-Manager and port-forwarding session contents do not receive normal shell-content logging.

Be careful: the default ssm-user can have sudo privileges. Restrict IAM access and configure OS-level access appropriately.
